How Jev!Jev handles data

Backstage does not store your cases, runs or provider keys on our server.

Use made-up or redacted cases. A case you run passes through our server and goes to each provider you select. This page describes the storage and requests visible in the code; it cannot promise what a provider or other infrastructure keeps.

What we keep

Ticket office. With your consent, the form puts your ticket number, submission time, ticket type, selected show, email, optional website and idea, follow-up choice, consent flag and retry identifiers in a SQLite file on our server. The form promises that these details are never shared or sold; the application code does not send ticket rows to another service.

Sign-in. If Backstage sign-in is enabled, an operators file on our server holds approved email addresses, optional display names and password hashes. A signed session cookie contains the email and session details, is marked HttpOnly, and lasts up to 12 hours. A sign-out can add the session id and expiry to a revocation file on our server. Google sign-in uses a short-lived cookie during sign-in.

Logs and trial accounting. Backstage event logs go to the server journal. They contain sign-in email and IP address, request ids, run provider and model, API route and status, and ticket ids or rejection reasons. They do not include case text in the event fields. nginx also has a web access log configured. If a funded trial is available, its SQLite ledger holds allowance, network bucket, reservation, cost and day data; it has no case, question, answer or key column.

What we do not keep

Backstage does not write your cases, questions, answers, labels, runs or provider keys to its server files or databases. Your unfinished scene draft, including cases and question text, is saved in this tab's sessionStorage. It can survive a reload and is cleared by the clear action or when the tab closes. The active run and keys are held in page memory. Clear keys stops further calls; closing the page loses the run. If you download records or run evidence, the browser saves your own copy.

The server temporarily reads each submitted case and key to relay a request. The statement above concerns persistent storage by this application, not transient request handling or storage by a provider.

What leaves your browser

For each model you select, the browser sends the case, question, choice definitions and credential through the Backstage server. The server sends them to that model's provider. A local keyword rule does not call a provider.

How long

The scene draft lasts in this tab until it is cleared or the tab closes; a live run lasts only while the page stays open. A sign-in session cookie has a 12-hour maximum age, the temporary Google sign-in cookie 10 minutes, and a funded trial cookie 90 days. The journal configuration requests a one-day maximum retention for Backstage event logs, with one-hour file rotation. The trial ledger prunes settled reservations and eligible allowances after 90 days, but keeps uncertain spend for reconciliation. The ticket office has no automated deletion in code. Its published wording describes a plan for manual deletion, but the retention period is not settled here. The web access log's retention is not set in this repository.

How to get your data deleted

To request deletion of a ticket office row, open a GitHub issue quoting your ticket number, as the ticket form instructs. Do not put your email, case text or provider key in a public issue. The code has no self-service ticket deletion route; an operator must handle the request. For a draft, use the Backstage clear action or close the tab. For a signed-in session, sign out to revoke it. How to request deletion of other server-side records is still undecided.

Not decided yet

  • The retention period and manual deletion schedule for ticket office rows. The form publishes a plan, but code does not enforce it.
  • Whether the form's never shared or sold promise has been verified for manual handling and infrastructure outside the application code.
  • How to request deletion of operator account records, revocation records, logs or trial ledger records, and how completion of a ticket deletion request is confirmed.
  • Retention of the nginx web access log, and retention and deletion by model providers and other infrastructure beyond the application code.
