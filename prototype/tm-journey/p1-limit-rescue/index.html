Act 1 · What this is

Jev is the product: TokenMax is one use of it

TokenMax is the flagship example for Jev!Jev. It is being designed, and might be built if enough people need it. Part of it you can use today; the rest is still on paper.

Design, not built

The TokenMax router

A token router that would keep you from hitting your weekly limit by pacing the week. Fixed rules would send most jobs; Jev would pick the cheaper door for the jobs the rules cannot route. In rehearsal, not run (issue 236). No result yet.

Built today

The map

Your last 7 days of Claude Code and Codex, drawn on your own computer, in two reports.

Built today

The share link and the board

Your map prints a link; open it and press Share to post your week's totals to the board. Newest first, self-reported, not verified. See the board

Through jevnotjev, TokenMax is gathering weeks from willing people. Each week shared helps decide whether the router gets built.

Your map shows

  • How many sessions you ran in Claude Code and in Codex, and how many had helper work running alongside.
  • Each time you hit a limit: the short window, the weekly window, or unknown, and when it first hit (UTC).
  • How much output each tool wrote, and what share of Claude output came from the big Opus model.
  • How much of the Codex week was used at the last reading.

It does not

  • Say what caused a limit.
  • Turn counts into a cost or a percent of your plan.
  • Read your messages. The only text it reads is Claude Code's own limit notice.
  • Send anything anywhere.

Act 2 · Your ticket

Should you share your week?

Admit one

  • You use Claude Code or Codex on this computer.
  • You have run out mid-task and would rather pace it and use it all.
  • You want a say in whether the router gets built.

What it asks of you

  • One line to paste, shown in the next act.
  • It looks at your last 7 days unless you ask for more.

What stays yours

  • Two reports in a new folder on your computer. Nothing is sent.
  • If you share, only your week's totals go: no paths, project names, ids or times.

Not sure yet? See the example week first.

Act 3 · Curtain up

Make your map

What the line does: it reads the Claude Code and Codex history on your own computer and writes two reports into a new folder there. It never overwrites an earlier report.

What leaves: nothing, until you open the link it prints and press Share. Then only your week's totals go: counts, with no paths, project names, ids or times.

Nothing happens, or it asks for Bun?

The line needs Bun, a program that runs it. Paste this first, press Enter, then come back for the line below.

curl -fsSL https://bun.sh/install | bash
Want more than a week?

It reads the last 7 days unless you ask. Add --days 30 to the end of the line for 30 days. Shared maps go up to 90 days.

Want to read it before you run it?

The line fetches one file from this site and runs it. Read map.ts.

Open a terminal on the computer where you use Claude Code or Codex, paste this line and press Enter.

curl -fsSL https://jevnotjev.breakoutwithai.com/tm/map.ts | bun run - --share

The example week

One builder's real week, 7 days to 16 Oct 2026

Limits

2 limit hits: 1 short window, 1 unknown window. Both on Wed 14 Oct, from 16:20 UTC.

The report says when, not why.

Claude Code

515 sessions · 9,977,232 output tokens · 87% of that output on Opus, the big model.

Codex

3,478 sessions · 7,503,143 output tokens · weekly window 15% used.

Helper work

444 sessions had helper work running alongside.

Proposals (not measured savings)

For a week like this, the report proposes:

  • 2 limit episodes: put must-deliver work early in the window and queue optional work for after the reset.
  • 87% of Claude output came from Opus-class models: test whether routine helper work holds quality on a smaller model before moving it.

Not covered

Token counts are not a percent of your plan or a cost.
